# BiologicalAGI Public Glossary v0.1

## Status

Public-safe documentation draft.

This glossary is intended to provide high-level orientation terms for BiologicalAGI-Hub. It does not activate runtime functionality, automation, agents, bots, workers, deployment tooling, or production services.

This glossary is intentionally limited to public-safe orientation terms. It is not a complete map of SCOS, BiologicalAGI, private governance methods, sandbox concepts, or future runtime work.

Glossary entries describe documentation concepts only. They do not imply active runtime systems, automation, agents, bots, deployment, or production readiness.

## Glossary Rules

Each term is written to remain:

- plain-language
- high-level
- documentation-first
- public-safe
- free of runtime claims
- free of automation claims
- free of production-readiness claims
- bounded by review and approval language

## Terms

### BiologicalAGI-Hub

BiologicalAGI-Hub is a documentation and navigation hub for selected BiologicalAGI and SCOS-related projects.

It helps readers understand the ecosystem, review project orientation materials, and identify what is safe to explore.

Boundary:

- It does not claim to link every project.
- It does not provide runtime functionality.
- It does not activate automation, agents, bots, workers, or deployment tooling.

### SCOS

SCOS is a structured governance and documentation framework for organizing complex project work through evidence, consent, review, and staged action.

It supports careful project navigation by separating what is verified, what is planned, what is blocked, and what needs human approval.

Boundary:

- This glossary does not claim SCOS is a production runtime.
- This glossary does not claim SCOS is an autonomous AI system.
- This glossary does not claim active service behavior unless separately verified.

### SCOS Principles

SCOS principles are plain-language rules used to keep complex project work safe and reviewable.

Core principles include:

- orientation before execution
- evidence before claims
- consent before action
- handoff before automation
- human approval before irreversible change

Boundary:

- These are governance principles.
- They should not be described as automatic enforcement unless a specific enforcement mechanism is separately verified.

### Accessibility Scaffold

Accessibility Scaffold is a documentation and interaction approach that makes complex systems easier to navigate, review, and safely use.

It supports clearer entry points, safer instructions, reduced confusion, and better handoff between people, tools, and project records.

Boundary:

- It is not a medical, clinical, or therapeutic system.
- It should be presented as a usability and documentation support pattern.

### Warehouse / Archive

Warehouse / Archive is a modular knowledge organization model.

The warehouse preserves source material, records, and project artifacts. The archive or catalog layer helps organize and navigate those materials through curated views.

Boundary:

- It does not imply autonomous memory.
- It does not imply hidden monitoring.
- It should be described as a documentation and organization model.

### Living Archive Mode

Living Archive Mode is a documentation pattern for preserving evolving project state.

It separates stable records from active working notes so future reviews can understand what changed, why it changed, and what remains unfinished.

Boundary:

- It is documentation-first.
- It does not imply live automation or autonomous update behavior.

### Repository Maturity Categories

Repository Maturity Categories are review labels used to describe the current documentation state of a repository.

Example categories:

- Placeholder / Minimal README
- Incomplete / Needs Context
- Advanced / Needs Simplified Entry
- Governance-Focused
- Runtime-Sensitive / Requires Review

Boundary:

- These categories are review states, not permanent judgments.
- They should be updated when evidence changes.

## Terms Intentionally Omitted

Some additional internal governance, sandbox, prototype, and research terms are intentionally omitted from this public glossary pending further review.

This omission protects public/private boundaries and avoids presenting internal vocabulary, future sandbox ideas, or prototype language as public-facing concepts before they are separately reviewed.

## Final Boundary

This glossary does not authorize automation, runtime, agents, bots, workers, GitHub Actions expansion, deployment, repository settings changes, licensing changes, or bypasses.
